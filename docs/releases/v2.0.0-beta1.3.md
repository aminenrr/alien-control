**Alien Controls 2.0.0-beta1.3** (pre-release): safety and reliability fixes on top of beta1.2, from the 2.0 code review. Nothing new to look at apart from one Lights hint. Everything else is the same as beta1.2. The in-game overlay comes in beta 2.

### Fixed
- **RTX off and the GPU overclock**: an overclock write that was already running when you confirmed iGPU only could still hold NVML while the RTX was being removed (the same native crash 1.2.0-beta.4 fixed for the power readout). The overclock and the power readout now share one NVML session, and turning the RTX off (or back on) waits for the call in flight, then blocks NVML until pnputil is done.
- **Overclock and CPU cap after a crash, logoff or shutdown**: a crash, signing out or shutting down skipped Quit's cleanup, so a kept overclock could stay on (also on battery) until a reboot, and the Quiet 3.0 GHz cap stayed in the power plan. The app now puts the overclock back to +0 and clears the cap when it crashes or when Windows ends the session. At startup it reads the offsets the driver really runs (on AC) instead of assuming +0, and if settings.json and its backup are both unreadable it writes +0 once.
- **Reset settings**: it skipped Quit's cleanup, so a Quiet (or Custom Efficient) CPU cap stayed on after the restart, and it could freeze the window for up to 4 s. It now runs the same cleanup as Quit, without the iGPU prompt.
- **Two light animations at once**: quick swatch clicks with Spectrum or Rainbow on (or a brightness change during a click) could start two animation loops. The keyboard flickered and one loop kept painting over Static until a restart. Only one runs now, and every lighting change waits for the one before it.
- **F1, presets and power modes at the same time**: a second F1 press while the first was still switching sent "G-Mode on" again, and F1, the Home switch, the tray, the Home tiles, F2, Auto preset and resume could overlap and leave the CPU cap or the refresh rate from the other preset. They now run one at a time. A quick second F1 means off (its toast says so), and the Home switch greys out while F1 is switching. Follow-ups that came in during a change (the mode re-read, a status key, the +0 on unplug during an overclock write) now run right after it instead of being dropped.
- **Minimized window kept polling**: minimizing kept every sensor read running (and kept the RTX awake). Minimized now polls nothing, and restoring starts it again.
- **Keyboard stuck dark after the timeout**: a key press during the last step of the backlight fade could leave the keys lit but every later frame held (colours, status keys, Ctrl + Alt + F) until the next timeout. Fixed, and the held frame can no longer overwrite a newer one.
- **Run on startup**: the logon task file went through %TEMP% unlocked before Task Scheduler read it. It is now locked and checked while schtasks reads it. A task that still points at an older copy of the app (a new zip extracted somewhere else) is rebuilt for the exe you are running.
- **Refresh rate with an external monitor**: presets and the 60 / 240 Hz buttons changed the primary display, so an external monitor set as primary got 60 Hz on Battery and every other preset failed with "240 Hz isn't offered". They now always target the laptop panel (the primary display only when the lid is closed).
- **Stuck Windows tools**: pnputil, net and powercfg had no time limit. They now time out and their output is read safely. A pnputil that takes longer than 60 s is reported in the status line but never killed (it is left to finish turning the RTX off or on).
- **Lights hint**: EFFECT AND BRIGHTNESS reads **CTRL + ALT + F · LIGHT LEVEL** (was F7 · KEYBOARD LEVEL), and the Keyboard tile tooltip says Ctrl + Alt + F cycles the light level.
