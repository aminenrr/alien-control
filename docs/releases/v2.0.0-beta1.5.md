**Alien Controls 2.0.0-beta1.5** (pre-release): a fix for beta1.4's Run on startup copy, found on the laptop. Same layout and features as beta1.4.

### Fixed
- **Sensors and shortcuts dead after a reboot.** beta1.4 copies the app to `C:\Program Files\AlienControl` for Run on startup, but it only took the alienfx-tools CLIs from a `tools\` folder. If `alienfan-cli.exe` and `alienfx-cli.exe` sit next to `AlienControl.exe` instead, the copy had neither, so after a reboot every Home reading showed `--` and the presets, G-Mode and other shortcuts did nothing. Both CLIs are now copied from either place (they are still hash-checked before every run).
- **NVIDIA tray icon check.** After iGPU only, the app restarts NVIDIA's Display Container and then waits for its tray process. It was watching `nvcontainer.exe`, which is the NVIDIA app's process and runs either way. It now waits for a new `NVDisplay.Container.exe` in your session, so crash.log says whether the restart really brought it back.

### How to update
Run beta1.5 from the folder you extracted it to (or anywhere): with Run on startup on, it updates the Program Files copy, CLIs included. If you copied the two CLIs by hand, nothing else is needed.

### What to test
Tested on the m15 R7 on 2026-10-24: everything works.

- [x] Extract beta1.5 next to your CLIs and run it once. `C:\Program Files\AlienControl` now has `alienfan-cli.exe` and `alienfx-cli.exe`, and crash.log has a `Startup` line about the update.
- [x] Reboot. Home shows temperatures, fans, CPU and GPU use, RAM and VRAM within a few seconds.
- [x] After the reboot, F2 / F3 / F4, G-Mode and Ctrl+Alt+F all work.
- [x] iGPU only, then Advanced Optimus: the NVIDIA tray icon comes back, and crash.log's `NvidiaTray` line says "NVDisplay.ContainerLocalSystem restarted, tray process up after N s".
- [x] Turn Run on startup off, then on again: the Program Files folder is removed, then copied again with both CLIs.
